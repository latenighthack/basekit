# basekit

basekit is a Kotlin Multiplatform toolkit for building apps whose UI logic lives once, in shared
Kotlin, and is projected onto each platform's native UI by generated bindings. It is three
independent KSP codegen **slices** you adopt à la carte:

- **navigation** — annotate destination interfaces (`@Destination`, `@Route`, `@NavigateTo`) and
  basekit generates a type-safe navigation graph: one navigator interface per screen that names
  exactly the destinations it can reach, plus a deep-link route table.
- **viewmodel** — annotate a `@ViewModelSpec` interface over a `ViewModel<State>` and basekit
  generates native binding wrappers per platform: an Android `Abstract{Vm}Activity`, iOS
  `Kvo{Vm}` (KVO/UIKit) and `Observable{Vm}` (SwiftUI) Swift wrappers, and a React `use{Vm}` hook.
- **tui** — bind a ViewModel to a destination with `@TuiScreen` and basekit generates a
  [TamboUI](https://github.com/tamboui/tamboui) terminal UI over the same ViewModels, so shared
  logic is runnable in a terminal. Preview.

A generated **test harness** lets you drive whole navigation journeys in a plain unit test.

## Status

Pre-1.0 (`0.2.0`). No binary-compatibility guarantee yet; the public API may change between minor
versions. Supported targets: `jvm`, `android`, `iosArm64`, `iosX64`, `iosSimulatorArm64`,
`macosArm64`, `macosX64`, `js` (IR). The `tui` slice is a preview and depends on a snapshot build of
TamboUI (see below).

## Install

Artifacts are published to Maven Central under `com.latenighthack.basekit`.

```kotlin
// settings.gradle.kts
dependencyResolutionManagement {
    repositories {
        mavenCentral()
        google() // for the Android bindings
    }
}
```

Pull in only the slices you use. Each slice is a runtime library + an annotations artifact + a KSP
processor:

| Slice | Runtime | Annotations | Processor (KSP) |
|---|---|---|---|
| navigation | `basekit-navigation` | `basekit-annotations` | `basekit-ksp` |
| viewmodel | `basekit-viewmodel` | `basekit-viewmodel-annotations` | `basekit-viewmodel-ksp` |
| tui | `basekit-tui` | `basekit-tui-annotations` | `basekit-tui-ksp` |
| test harness | `basekit-navigation-test` | — | (generated by `basekit-ksp`) |

```kotlin
// build.gradle.kts (a KMP module)
plugins {
    kotlin("multiplatform")
    id("com.google.devtools.ksp")
}
kotlin {
    sourceSets.commonMain.dependencies {
        implementation("com.latenighthack.basekit:basekit-navigation:0.2.0")
        implementation("com.latenighthack.basekit:basekit-viewmodel:0.2.0")
    }
}
dependencies {
    add("kspCommonMainMetadata", "com.latenighthack.basekit:basekit-ksp:0.2.0")
    // …see "Wiring KSP" below for the per-target processor wiring the viewmodel slice needs.
}
```

> The `tui` slice additionally needs TamboUI, which is snapshot-only today. Add the snapshot repo and
> the toolkit yourself (see [the tui slice](#the-tui-slice)).

## Quickstart

Declare a screen as one interface that is at once the navigation destination, the view model, and
(optionally) its own terminal screen:

```kotlin
@Destination
@ViewModelSpec
interface HomeViewModel :
    NavigationDestination<HomeViewModel.Args>,
    ViewModel<HomeViewModel.State> {

    @Route("/")
    class Args : NavigatorArgs()

    data class State(val title: String)

    // Two call sites to the same destination → a generated DetailSource enum distinguishes them.
    @NavigateTo(DetailViewModel::class)
    suspend fun onOpenDetail()

    @NavigateTo(DetailViewModel::class)
    suspend fun onOpenDetailFromBanner()
}

@Destination
@ViewModelSpec
interface DetailViewModel :
    NavigationDestination<DetailViewModel.Args>,
    ViewModel<DetailViewModel.State> {

    @Route("/detail/{id}")
    class Args : NavigatorArgs() {
        @RouteArg var id: String by storedProperty()   // bound from the matched URL
    }

    data class State(val id: String, val count: Int)

    suspend fun onIncrement()          // zero-arg suspend → an "action"
    suspend fun onSetNote(note: String) // single-arg suspend → a "mutator"
}
```

From that, the navigation processor generates (into the package you choose):

```kotlin
interface DetailNavigationTarget {
    fun navigateToDetail(args: DetailViewModel.Args, source: DetailSource, context: Any? = null)
    enum class DetailSource { HOME_ON_OPEN_DETAIL, HOME_ON_OPEN_DETAIL_FROM_BANNER }
}
// The navigator injected into HomeViewModel — it can reach exactly Detail (and close):
interface HomeNavigator : CloseNavigationTarget, DetailNavigationTarget
// A deep-link table: GeneratedRoutes.register(routeTable) maps "/detail/{id}" → Args{ id = … }
object GeneratedRoutes { fun register(table: RouteTable) { /* … */ } }
```

Your ViewModel implementation takes the generated navigator and calls it explicitly — navigation is
never inferred from the graph; the graph only defines the interfaces and tracks call sites:

```kotlin
class RealHomeViewModel(private val navigator: HomeNavigator) :
    HomeViewModel, StatefulViewModel<HomeViewModel.State>(HomeViewModel.State("Feed")) {
    override suspend fun onOpenDetail() =
        navigator.navigateToDetail(DetailViewModel.Args().apply { id = "42" },
            DetailNavigationTarget.DetailSource.HOME_ON_OPEN_DETAIL)
}
```

A [`RespondingDestination<Args, R>`](basekit-navigation/src/commonMain/kotlin/com/latenighthack/basekit/navigation/RespondingDestination.kt)
makes its `navigateTo…` a `suspend` function returning `R?` — the picker pattern: open, await the
choice, `null` on dismiss.

### Platform bindings

The viewmodel processor emits, per `@ViewModelSpec`:

- **Android** — `Abstract{Vm}Activity` extending `BaseActivity`. Subclass it, supply the view, and
  override `onStateChanged(state)`. The ViewModel is retained across configuration changes and state
  is collected under `repeatOnLifecycle(STARTED)`.
- **iOS** — `Kvo{Vm}.swift` (an `NSObject` exposing State as `@objc dynamic` KVO properties, for
  UIKit) and `Observable{Vm}.swift` (an `ObservableObject` with `@Published` state and two-way
  `Binding`s for mutators, for SwiftUI). Delivered as **source**; a consuming Xcode/SwiftPM target
  compiles them alongside the exported KMP framework. Collect them with the
  `collectBasekitViewModelSwift` Gradle task.
- **Web** — a `@JsExport use{Vm}(viewModel)` React hook.

## Wiring KSP

basekit ships convention plugins in-repo; a published `com.latenighthack.basekit.*` Gradle plugin is
planned. Until then, wire the processors directly. This is what the plugins do — it is not more than
this:

**navigation** (pure common types, generated in the metadata pass):

```kotlin
dependencies { add("kspCommonMainMetadata", "com.latenighthack.basekit:basekit-ksp:0.2.0") }
kotlin.sourceSets.named("commonMain") {
    kotlin.srcDir(layout.buildDirectory.dir("generated/ksp/metadata/commonMain/kotlin"))
}
ksp { arg("Basekit_NavigationPackage", "com.example.app") } // where the navigators land
// Make every other ksp task run after the metadata pass:
tasks.matching { it.name.startsWith("ksp") && it.name != "kspCommonMainKotlinMetadata" }
    .configureEach { dependsOn("kspCommonMainKotlinMetadata") }
```

**viewmodel** (per-platform code, so add to every target's ksp configuration):

```kotlin
dependencies { add("kspCommonMainMetadata", "com.latenighthack.basekit:basekit-viewmodel-ksp:0.2.0") }
kotlin.targets.configureEach {
    if (name == "metadata") return@configureEach
    add("ksp" + name.replaceFirstChar { it.uppercase() },
        "com.latenighthack.basekit:basekit-viewmodel-ksp:0.2.0")
}
```

To also generate the **test harness**, add `arg("Basekit_GenerateTestNavigator", "true")` and depend
on `basekit-navigation-test` in `commonTest`/`commonMain`.

See the working setup in [`demo-core/build.gradle.kts`](demo-core/build.gradle.kts) and the
convention plugins under [`build-logic/`](build-logic/src/main/kotlin).

## Annotations

| Annotation | Slice | On | Purpose |
|---|---|---|---|
| `@Destination(webPath, navName)` | navigation | interface | Marks a navigable destination; `navName` disambiguates colliding names |
| `@Route(path)` | navigation | `Args` class | Deep-link template, e.g. `/detail/{id}` |
| `@RouteArg` | navigation | `Args` property | Binds a path param from the URL (must be `String`) |
| `@NavigateTo(target)` | navigation | function | Declares a navigation edge from this action to `target` |
| `@ViewModelSpec(webPath)` | viewmodel | interface | Marks a ViewModel; drives the platform binding codegen |
| `@ViewModelList(possibleTypes)` | viewmodel | property | A `Flow<Delta<ChildVm>>` list of child ViewModels |
| `@ChildViewModel` | viewmodel | property | A single nested child ViewModel |
| `@ViewModelInject` | viewmodel | class | Wires a concrete impl into the generated kotlin-inject module |
| `@ViewModelModule` | viewmodel | interface | App-supplied kotlin-inject providers the component includes |
| `@TuiScreen(destination, implementation)` | tui | interface | Binds a ViewModel to a destination as a terminal screen |
| `@CodegenIgnore` | all | element | Excludes an element from codegen |

## KSP options

| Option | Slice | Meaning |
|---|---|---|
| `Basekit_NavigationPackage` | navigation, tui | Package the generated navigator/route types land in |
| `Basekit_GenerateTestNavigator` | navigation | `"true"` also generates the test harness |
| `Basekit_TuiPackage` | tui | Package (in a dependency) the TUI processor scans |
| `Basekit_TuiAppComponent` | tui | FQN of an app DI root the generated component takes as a parent |
| `basekit.viewmodel.swiftFrameworkImports` | viewmodel | Comma-separated frameworks the generated Swift should `import` |

## Testing navigation journeys

With `Basekit_GenerateTestNavigator=true`, basekit generates a `TestViewModelRegistry` (one factory
method per `@Destination` — an unwired screen is a **compile error**) and a `TestClientNavigator`
that records every navigation. A test drives real ViewModels through the real navigator:

```kotlin
val navigator = TestClientNavigator(DemoRegistry())
navigator.launch(HomeViewModel.Args())
val home = navigator.awaitViewModel<HomeViewModel>()

home.onOpenDetail()
val detail = navigator.awaitViewModel<DetailViewModel>()
assertEquals("42", detail.initialState.id)
```

You implement the registry once — one line per destination, delegating to your DI. See
[`demo-core/src/jvmTest/.../DemoRegistry.kt`](demo-core/src/jvmTest/kotlin/com/latenighthack/basekit/demo/test/DemoRegistry.kt).

## The tui slice

TamboUI has no Central release yet, so add its snapshot repo and depend on it directly:

```kotlin
// settings.gradle.kts → dependencyResolutionManagement.repositories
maven("https://central.sonatype.com/repository/maven-snapshots/") { mavenContent { snapshotsOnly() } }
```
```kotlin
// build.gradle.kts (a JVM module)
implementation("com.latenighthack.basekit:basekit-tui:0.2.0")
implementation("dev.tamboui:tamboui-toolkit:0.5.0-SNAPSHOT")
runtimeOnly("dev.tamboui:tamboui-jline3-backend:0.5.0-SNAPSHOT")
```

`basekit-tui` declares TamboUI as `compileOnly`, so it never leaks a snapshot dependency into your
published app — you choose the TamboUI version. See [`demo-jvm`](demo-jvm) for a runnable example.

## Building from source

```
./gradlew build          # compiles every target and runs the JVM/native test suites
```

Requires JDK 17 and (for the Apple targets/frameworks) macOS. The `js` npm lockfile is committed
under `kotlin-js-store/`; if you change JS dependencies, run `./gradlew kotlinUpgradePackageLock` and
commit the result.
